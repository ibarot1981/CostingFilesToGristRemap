Deployed Safari Grist schema v10 · 8 October 2026

Parts: identity, composition and purchase evidence

Safari Manufacturing Grist is canonical for Part business records. Each physical design has one permanent identity and number. Metadata, engineering revision, manufacturing composition and vendor purchase history remain separate records.

Production migration: schema v9 added ten costing/configuration tables and PartComponentRevision.SourcingRoute. Additive v10 added PartIntendedSharingState, PartIntendedModelCode, PartIntendedSharingEvent and PartRegistryRequest.Payload after a separate verified native Grist backup. No field types changed; legacy Part/revision rows, 313 LineMaster rows and workbook snapshots were preserved. No synthetic business rows were written to production. Disposable Grist checks verified cascade creation/edit, audited sharing, Live no-write, save recovery and frozen history; test documents are in Trash.

The old PurchasedPartCostEvidence table is retained for compatibility; its write endpoint returns HTTP 410.

Current rate means latest eligible actual purchase by transaction time across vendors. Quotes, drafts, voids and returns are excluded. Discount is deducted; tax, freight and other charges are excluded. Equal-time conflicting rates or an incomparable newest transaction are review-needed. No history means unavailable, not zero. MaterialRateLog/default pricing is unchanged.

Implemented costing behavior · D070

Current Part metadata and eligible rates feed disposable Live Cost without historical writes. Only explicit Save Cost Snapshot freezes normalized Part occurrences, cost lines and selected evidence. The old purchase-rate evidence API returns 410. Snapshot reads check the normalized row checksum and never resolve current rates.
